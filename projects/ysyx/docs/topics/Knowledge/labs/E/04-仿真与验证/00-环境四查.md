## 讲义判据到本地判据的转化

讲义只要求"运行以下命令来检查安装是否成功，以及版本是否正确"。本地扩成四项：讲义环境（Verilator）、仿真配套（GTKWave）、板卡（NVBoard 可编译）、工程入口（NPC_HOME）——后面三样批 2/3 立刻要用，现在一并验掉。

## 四项记录

### 1. init.sh npc + NPC_HOME

```bash
cd /workspace/ysyx-workbench && ./init.sh npc   # 沙箱内默认 cwd 即 ysyx-workbench
```

实测（2026-11-12）：exit 0；输出 "Environment variable NPC_HOME has been added into /home/sandbox/.bashrc"；`source ~/.bashrc` 后 `echo $NPC_HOME` = `/workspace/ysyx-workbench/npc`；`ls $NPC_HOME` = Makefile、csrc、vsrc。init.sh 的 npc 分支只做 addenv（目录已初始化时跳过克隆）。

### 2. Verilator

实测：`command -v verilator` = `/toolchains/verilator-5052/bin/verilator`；`verilator --version` = `Verilator 5.052 2026-09-05 rev 5.052-983a06a`。平台经 profile toolchains 键暴露在 /toolchains/ 下，PATH 已含。讲义判据（版本正确）通过；讲义"从 git 安装"一节跳过（平台规矩：专用工具在项目内不重装），STFW/RTFM 照做。

### 3. GTKWave

实测：`command -v gtkwave` = `/usr/bin/gtkwave`；`gtkwave --version` 报 "Could not initialize GTK! Is DISPLAY env var/xhost set?"——无 DISPLAY 环境（Run 模式）的预期失败，不是缺失。GUI 批次走 `-Gui`。判据按"在位"通过，版本号留批 2 -Gui 时补记。

### 4. NVBoard 可编译

nvboard 顶层无 Makefile（它是"库"：`scripts/nvboard.mk` 被工程 include）。可编译判据落在编译其自带 example：

```bash
cd nvboard/example && NVBOARD_HOME=/workspace/ysyx-workbench/nvboard make
```

第一跑 no-op（build/top 是 2026-10-13 旧产物，"Nothing to be done"不算编译证据）——按"判据要实测"加严为 `make clean` 后全量重编。实测（2026-11-12）：exit 0；Verilator 报告 8 模块，walltime 32.6s；build/top 重新生成（当日 20:07）。

## 结论与坑

1. 四项全过，批 0 完成
2. 坑 1：nvboard 无顶层 Makefile，"可编译"要落到 example 或接入工程上
3. 坑 2：no-op 不算证据，判据必须产生新的产物或新的输出
4. 沙箱内路径视图：Run 任务里项目=/workspace/ysyx-workbench、工具链=/toolchains/<键>；Doctor 报的 /mnt/wsl-sandbox/studylab 在 Run 任务内不可见（实测 ls 为空）——引用路径一律 /workspace/...
5. 原始日志：卷内 logs/ysyx/studylab-ysyx-20261112T1204*.stdout.log 等 5 个 run 日志（平台记录制，不整段粘贴）
