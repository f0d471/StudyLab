# Knowledge：知识库

定位一句话：**教程完全自足**。官方讲义的知识汲取进这里，复习不需要再翻网页镜像；原始资料（离线镜像、RISC-V 手册）只作对照与最终兜底。

## 目录

| 目录 | 收录范围 | 维护方式 |
| --- | --- | --- |
| [tutorials/](tutorials/) | 主线教程，按讲义阶段组织（F/E/D/C/B/A 各一目录） | 一部分一篇；讲义必答题随篇作答 |
| [fundamentals/](fundamentals/) | 前置基础知识：主线不方便展开的罗列型内容 | 用到才加，不预先写全；没被任何教程引用的篇不开 |
| [labs/](labs/) | 课程实验记录：命令、判据、实测输出 | 按讲义阶段建目录，每个实验写清判据 |

三层的关系：教程是主线（"这件事为什么存在、怎么一步步做出来"），fundamentals 是前置与案头手册（"这个名词是什么、这条指令每个字段是什么、这个函数每个参数什么语义"），labs 是动手与判据（"做没做对，机器说了算"）。教程正文里遇到 fundamentals 覆盖的名词，用一句 `[基础]` 跳转，不展开；遇到罗列型内容（成堆的指令编码、CSR 位段、函数清单），指到 fundamentals 对应篇，不逐条抄进正文。

## 体例

1. **命令完整给，参数注明在管什么。** 每个参数第一次出现时注释标清作用；读者不对照网页也能照跑。
2. **代码完整给，逐行讲。** 关键行的讲解紧跟代码块；能跑的实验代码放 labs/ 对应目录。
3. **判据跟着实验走。** 没有判据的实验等于没做；每条判据都要能"注错见红"。
4. **数字必须实跑。** 输出、耗时一律来自本机真跑并注明日期，不照抄讲义；环境不在线时沿用已归档实测，不编造。
5. **真实描述优先于比喻。** 事物的身份和工作机制按真实情况讲（例：`ebreak` 是"触发调试停机的指令，NEMU 把它当作程序正常退出的约定入口"），比喻至多一句辅助。
6. **讲义勘误与版本差异就地标注。** 讲到与讲义或手册不一致处，注明"讲义写的是 X，手册/实测是 Y"，并写明各自版本。
7. **开头交代出处。** 每篇注明讲义版本与章节链接（或手册章节）；新术语先给中文含义、全称和具体对象，再讲机制。

文档通用最低要求（术语、引用、实验记录格式）见[资料目录 README](../../README.md)第四节。
