## 1 波形是什么：第一个 VCD

### 1.1 [做 L2] 给第 01 章的 testbench 加波形

先看现象。把第 01 章的双控开关 testbench 加四行波形代码（完整文件在 labs 的
tb_vcd.cpp），编译时多给一个 `--trace`：

```bash
verilator --cc --exe --build -j 0 --top-module top --trace \
    --Mdir build/sw top.v tb_vcd.cpp
./build/sw/Vtop
```

`--trace` 是编译期开关：告诉 Verilator 在生成的模型里加进波形支持（没有它，模型类里
连 `trace()` 这个函数都没有）。跑完，`/tmp/top.vcd` 出现，屏幕上还是那十行打印。

### 1.2 打开这个文件看

VCD（Value Change Dump）是一个纯文本文件。本机实跑生成的 top.vcd 开头十九行：

```text
$version Generated by VerilatedVcd $end
$timescale 1ps $end
 $scope module TOP $end
  $var wire 1 " a $end
  $var wire 1 # b $end
  $var wire 1 $ f $end
  $scope module top $end
   $var wire 1 " a $end
   $var wire 1 # b $end
   $var wire 1 $ f $end
  $upscope $end
 $upscope $end
$enddefinitions $end


#0
1"
0#
1$
```

逐段读：

1. `$timescale 1ps`：仿真时间的最小刻度是 1 皮秒。dump 的计数单位就是它
2. `$scope module TOP` 与内层 `$scope module top`：两个作用域。外层 TOP 是 Verilator
   生成的顶层包装（第 01 章 3.1 节讲过这个根对象），内层 top 才是你写的模块，所以
   a、b、f 被声明了两遍，一遍在包装层、一遍在你的模块里
3. `$var wire 1 " a $end`：声明一根信号。列依次是：类型 wire、位宽 1、代号 `"`、名字 a。
   代号是文件内的一字母标识，a 分到 `"`、b 分到 `#`、f 分到 `$`（可打印 ASCII 里
   依次取，与信号名没有对应关系）
4. `#0`：时间戳。从这行起，直到下一个时间戳，都属于仿真时间 0
5. `1"`：值变化行。意思是"代号 `"` 的信号（就是 a）在当前时刻变成了 1"。`0#` 即 b=0，
   `1$` 即 f=1

把第 1 节的打印和这段对照：testbench 第一轮 `a = 1, b = 0`，eval 之后 `f = 1`，
所以时间 0 处三个值变化行正好是 `1"`、`0#`、`1$`。波形文件里没有秘密，它就是把这些
值变化按时间顺序存了下来。

### 1.3 这四行代码各干什么

tb_vcd.cpp 从第 01 章的 tb_switch.cpp 改出来，改动不止加波形：判错那一套（context、
assert、seen 统计）整个撤掉了，这一版只管录波。新增的波形代码集中在下面几行
（完整文件见 labs；行尾编号是正文标注，labs 原文没有）：

```cpp
#include "verilated_vcd_c.h"     // 1 VCD 的 trace 类
...
Verilated::traceEverOn(true);    // 2 打开运行期总开关
VerilatedVcdC* tfp = new VerilatedVcdC;
top->trace(tfp, 99);             // 3 把 trace 对象绑到模型上，99 是记录层次深度
tfp->open("/tmp/top.vcd");       // 4 开文件
...
tfp->dump((uint64_t)t++);        // 每轮记一次：把当前所有信号值写进当前时刻
...
tfp->close();                    // 收尾关文件
```

三步结构（编译期 `--trace`、运行期开与绑、每拍 `dump`）对 FST 同样成立，第 2 节
复用。`dump` 的参数是时间计数：传几，这条记录就落在仿真时间几。这里每轮加一，
所以十轮记录分布在时间 0 到 9。时间不是仿真器自己走的，是你在 `dump` 的参数里给的。

### 1.4 波形文件写在哪：一条纪律

本库的波形一律写 `/tmp`。两个原因：

1. 磁盘：长时间录制会吃满磁盘。波形写在工程外的 /tmp，不混进工程目录
2. tracer：第 4 节会解剖 npc 的 git_commit 宏，它提交时执行 `git add . -A`，波形若落
   在 npc 目录里，每一次 make sim 都会把上百万字节的波形收进追踪提交

## 2 FST：同一份实验，另一种格式

### 2.1 [做 L2] 一万拍的计数器，两种格式各录一份

双控开关太小，比不出格式差异。labs 里的 cnt.v 是一个 32 位计数器，带同步复位端 rst：
rst=1 时清零，tb_cnt.cpp 在 t=0 复位一拍后拉低，之后每个时钟沿加一。tb_cnt.cpp 驱动它
一万拍，用条件编译宏 `USE_FST` 让同一个 testbench 编出两个版本：

```bash
verilator --cc --exe --build -j 0 --top-module cnt --trace \
    --Mdir build/cv cnt.v tb_cnt.cpp          # VCD 版
verilator --cc --exe --build -j 0 --top-module cnt --trace-fst \
    -CFLAGS -DUSE_FST --Mdir build/cf cnt.v tb_cnt.cpp   # FST 版
```

两个版本跑完，本机实测（2026-11-14）：

```text
/tmp/cnt.vcd   429272 字节
/tmp/cnt.fst    40613 字节   比值约 10.6
```

FST 大约是 VCD 的 1/50 是经验值（出处见依据表），随设计的信号数和翻转密度变化；本机
这一例是 10 倍上下。结论不受影响：同一场仿真的记录，FST 明显更小。

### 2.2 为什么小，代价是什么

VCD 是文本，每个值变化一行字符；FST（Fast Signal Trace）是 GTKWave 作者定义的二进制
格式，对信号声明和值变化做了压缩编码。代价只有一条：它基本只有 GTKWave 读。查看器
锁定 GTKWave 的话（本库就是），没有理由不用 FST：三步代码与 VCD 完全同构，只换头文件
（verilated_fst_c.h）、类名（VerilatedFstC）和编译开关（--trace-fst）。tb_cnt.cpp 顶部
的 `#ifdef USE_FST` 把这点差异集中在一处，可以对照着看。

## 4 一键仿真：make sim

### 4.1 [做 L2] labs 里的演示 Makefile

波形代码加好之后，每次改一行就要重敲两条长命令。把它们写进 Makefile 的一个规则，
`make sim` 一条命令完成编译加运行。labs 里的演示件（真实文件，可跑）：

```makefile
TOPNAME = top
VSRCS = top.v tb_table.cpp

sim:
	verilator --cc --exe --build -j 0 --top-module $(TOPNAME) \
		--Mdir build/obj -o $(CURDIR)/build/tablesims \
		$(VSRCS)
	./build/tablesims

clean:
	rm -rf build

.PHONY: sim clean
```

规则的结构：目标 `sim` 没有依赖（make 每次都执行它的命令），命令第一行调用 verilator
（`-o` 给绝对路径，是因为生成工程在 --Mdir 目录里 make，相对路径会落错地方，这是本库
踩过的坑），第二行运行产物。`make sim` 的输出以四行真值表结尾，退出码 0。

### 4.2 npc/Makefile 里那行不许动的命令

讲义的框架在 npc/Makefile 里预置了一条 sim 规则，其中有一行：

```makefile
$(call git_commit, "sim RTL") # DO NOT REMOVE THIS LINE!!!
```

它调用的是 ysyx-workbench 根 Makefile 里定义的 git_commit 宏。宏展开后做的事（根
Makefile 原文，逐行）：

1. `flock` 拿锁，防止和其他 git 操作互踩
2. `git branch tracer-ysyx`：确保追踪分支存在
3. 备份当前 git index，把工作区 detach 切到追踪分支
4. `git add . -A --ignore-errors`：把全部改动收进暂存，包括你刚写的代码
5. 以固定作者 tracer-ysyx 提交，提交说明里带 "sim RTL"、学号、机器信息
6. 切回工作分支，还原 index

这就是"一生一芯"的原创性追踪：每次仿真自动在追踪分支留一条带时间的记录。两个推论：
其一，这行删了或改了，追踪就断，断点补不回来，所以讲义和本库都把它列为红线；其二，
它 `add . -A` 的范围是整个工作区，第 1.4 节"波形只写 /tmp"的纪律就是为它设的。

在 npc/Makefile 里写自己的 sim 规则是讲义任务，归学员（验收与 4.1 相同：一条命令跑通，
`git log tracer-ysyx` 里能看到 sim RTL 记录）。labs 的演示件不碰 tracer，两边互不干扰。

## 5 另一种仿真器：iverilog 对照

### 5.1 为什么做这个实验

公司里常见的是 VCS、Xcelium、Questa 这些闭源工具，开源
这边还有 Icarus Verilog（iverilog）。换一个工具名，工作流几乎原样：写 testbench、编译、
跑、看输出。真正会踩的差异藏在语义和定位里。沙箱里恰好装着 iverilog 12.0，用它把同一
批实验重做一遍，差异就现形了。范式级的全景（事件驱动、编译式、两态四态怎么正交组合）
在 [fundamentals/01](../../../fundamentals/01-仿真器/01-两种范式与工具谱系.md)。

### 5.2 [做 L2] 同一个开关，两种答案

top.v 原样不动。testbench 换成 Verilog 写（iverilog 的 testbench 就是另一个 Verilog
模块，tb_top_iv.v）：initial 块里枚举四种输入，`#1` 后打印。编译运行各一条命令：

```bash
iverilog -o build/tabi top.v tb_top_iv.v && vvp build/tabi
```

verilator 侧沿用第 1 节的编译加运行。两边输出对照（本机实测）：

```text
verilator 版（tb_table.cpp）     iverilog 版（tb_top_iv.v）
a=0 b=0 f=0                     a=0 b=0 f=0
a=0 b=1 f=1                     a=0 b=1 f=1
a=1 b=0 f=1                     a=1 b=0 f=1
a=1 b=1 f=0                     a=1 b=1 f=0
```

同一张真值表。组合逻辑的语义两边一致，工具差异不影响正确性。

### 5.3 [做 L2] 四态对两态：未初始化的值

xu.v 是一个从不复位的自保持触发器（`r <= r`）。r 从未被初始化。两个 testbench 各跑
三拍后打印 r。iverilog 侧编译运行：

```bash
iverilog -o build/xui xu.v tb_xu_iv.v && vvp build/xui
```

verilator 侧与第 1 节同款命令，`--top-module` 和文件名换成 xu（`--Mdir build/xv`）。
打印结果（本机实测）：

```text
iverilog:    r=x        （四态语义：未初始化如实报告 x）
verilator:   r=0        （两态语义：没有 x，未初始化给默认值 0）
```

这是两种仿真器最实质的语义差异。四态用 x 把"我不知道"暴露给你：x 沿着用到它的计算
扩散开，输出跟着变 x，这种扩散叫 x 传染（fundamentals/01 第 4 节有实测）；两态没有
这个通道，未复位的寄存器悄悄是 0，问题要靠 `--x-initial unique` 之类的初值策略或
lint 兜底。展开见 fundamentals/01 第 4 节。

### 5.4 [做 L2] 延迟：#5 的三种命运

late.v 的触发器带赋值内延迟（`q <= #5 d`：时钟沿后再过 5ns 才更新）。三种跑法，本机
实测：

iverilog 原生支持延迟，编译运行各一条命令：

```bash
iverilog -o build/lti late.v tb_late_iv.v && vvp build/lti
```

tb_late_iv.v 用 `$monitor` 打印每个变化时刻。打印值按时间精度计：`timescale 1ns/1ps`
的 1ns 是时间单位、1ps 是精度，`%0t` 打的是精度数，所以 10ns 的一步打作 10000：

```text
t=0 d=0 q=x
t=10000 d=1 q=x
t=20000 d=1 q=1      ← t=15000 时钟沿采到 d=1，#5（5000ps）后 q 才变
t=25000 d=0 q=1
```

verilator 要加 `--timing` 才支持延迟，构建运行：

```bash
verilator --cc --exe --build -j 0 --timing --top-module late \
    --Mdir build/ltv late.v tb_late.cpp
./build/ltv/Vlate
```

tb_late.cpp 用 `contextp->timeInc()` 推进仿真时间（计数的单位同样是时间精度 1ps，
一步 5000）：

```text
t=15000 q=0          ← 时钟沿刚过
t=19000 q=0          ← #5 还没到
t=20000 q=1          ← 5ns 到期，q 更新
```

verilator 若显式关掉 timing 支持并全开警告（命令为 `verilator --lint-only --no-timing
-Wall late.v`）：

```text
%Warning-ASSIGNDLY: late.v:7:30: Ignoring timing control on this assignment/primitive due to --no-timing
%Error: Exiting due to 1 warning(s)
```

延迟被忽略并给出 ASSIGNDLY 警告。指南把 `--no-timing` 下三类延迟构造的处置写全了，
默认行为并不一样：延迟语句被忽略、报 STMTDLY，这条默认就开着，不加 `-Wall` 也致命，
构建当场失败（fundamentals/03 第 8 节有实测）；赋值内延迟被忽略、报 ASSIGNDLY，它
默认关着（代码风格类），要 `-Wall` 打开，打开后默认致命，上面两行就是这个组合的实跑
输出；网线延迟直接忽略、不警告。

## 6 已知的坑

1. timescale 不写，延迟对不上：late.v 起初没带 `timescale 1ns/1ps`，iverilog 跑完
   40ns q 始终是 x（延迟远没到期）；补上指令后 q 在 t=20000ps 更新。多文件编译时
   timescale 指令按文件顺序生效，被延迟的模块自己要带（第 5.4 节实验中踩过）
2. `-o` 的相对路径落错地方：--build 在 --Mdir 里执行 make，相对的 -o 路径解析在 Mdir
   之下。要么给绝对路径，要么用 Mdir 里的默认名 `V<top>`（第 4.1 节）
3. 旧波形冒充新结果：/tmp 里的波形不会自己消失，重跑前先删（labs 脚本开头
   就删，正文实验同理）
4. 1/50 是经验值：别在报告里写死，写自己实测的数（本机 10 倍，第 2.1 节）
5. `dump()` 的参数类型要给无歧义的整型（uint64_t），传 long 会撞上重载歧义编译错
   （tb_vcd.cpp 踩过）
