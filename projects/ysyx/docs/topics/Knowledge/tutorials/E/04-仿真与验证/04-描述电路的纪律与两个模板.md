## 1 描述电路 = 实例化 + 连线

手里有一张电路图，向别人描述它，你说的会是"这里有一个 D 触发器，它的 D 接着
选择器的输出"。这就是 HDL 该做的事：实例化（放一个元件）加连线（把引脚接对）。

Verilog 的三种建模方式离这件事各有多远：

1. 数据流建模（assign）：一条连线规则，最贴近"连线"
2. 结构化建模（实例化模块）：就是"放元件"
3. 行为建模（always 里写过程）：先在脑子里把电路翻译成"一步一步的动作"，再写下来。
   翻译这一步就是风险所在：翻对了等价，翻错了你描述的是另一个电路

讲义的立场：初学者跳过行为建模，用前两种写；要用触发器和选择器，用官方给的 Reg 与
MuxKey 模板（结构化地包好了行为建模的内核，[fundamentals/05](../../../fundamentals/03-描述电路/05-Reg与MuxKey模板逐行拆.md)
拆开看过）。

## 2 [做 L2] 两种写法，同一种电路

行为建模的风险在于多一层翻译。两个实验对照。

### 2.1 2 选 1 选择器

mux2a.v 用 assign 写（`assign y = s ? b : a;`），mux2t.v 用模板实例化写（MuxKey
两对键值）。MuxKey 的用法一句话：三个模板参数依次是键值对数、键宽、数据宽；端口
给输出、key 和一串打包的 (键值, 数据) 对，谁的键值命中 key 就输出谁的数据，全不
命中输出 0（内部实现与逐行拆解在 fundamentals/05）。mux2t.v 给的两对是 0 选 a、
1 选 b。两种写法放进同一个顶层，1000 组随机输入，独立判据逐组重算
（tb_eq2.cpp，labs 可跑）：mismatches=0。两种写法描述的是同一个电路。

### 2.2 带使能的计数器

cnta.v 是行为建模版（一个 always 写完复位与计数）；cntt.v 是模板版：

```verilog
wire [7:0] qn;
assign qn = q + 8'd1;                    // 下一拍的值是一条连线规则
Reg #(8, 8'd0) r0 (clk, rst, qn, q, en);  // 状态只存在模板触发器里
```

模板版把电路拆成了图纸上指得出名字的两样东西：一个加一器（连线）、一个带使能的
触发器（元件）。`Reg #(8, 8'd0)` 的两个模板参数是位宽（8）与复位值（0）；括号里
五个端口依次是 clk、rst、din（下一拍的值，这里接 qn）、dout（当前值，这里开出一根
q）、wen（写使能）。行为版把这幅图压缩进一个过程。200 拍随机使能对照（tb_eqc.cpp，
每 64 拍插一拍复位）：mismatches=0，两种写法逐拍一致。

对照实验说明的事：写法自由，电路同一。选模板的理由不在正确性，在第 1 节的翻译
风险与第 3 节的雷。

## 3 [做 L1] 行为建模的雷：一块组合逻辑推出锁存器

lat_bad.v 是行为建模最常见的失手：

```verilog
always @(*) if (en) q = d;
```

if 没有 else。电路语义上，en 为 0 时 q 该是什么没有说，工具只能给你一个"记住上一次
的值"的元件：锁存器。实测：`--lint-only -Wall` 报 `Warning-LATCH`，并且不开 -Wall
也报、默认致命，构建当场失败。补一个明确的 else（lat_good.v 的 `else q = 1'b0;`），
-Wall 下零警告。

这就是讲义三条规范的第 3 条（不用锁存器）的直接动因之一：锁存器的变化不受时钟
驱动，时序分析工具难以处理。三条规范摆在一起读：

1. 没深入理解事件模型之前，不用行为建模（第 4 节就是"理解"的清单）
2. 坚持行为建模的话，只用 posedge：混用 posedge 与 negedge 让时序收敛困难，增加
   后端物理实现难度。这条的理由在后端，本库不做物理实现，依据以讲义原文为准
3. 不用锁存器：本章实测了它是怎么被无意写出来的，lint 能拦（LATCH 默认致命）

用模板（或 Chisel）就绕开了这三条的雷区：模板内核只写 posedge、分支覆盖、纯组合。

## 4 事件模型四问（学员作业）

讲义给了四个问题，答不上来就别用行为建模。作答归学员；本节把作答要用的材料摆齐，
每问附检验标准：答案要能落到一条标准条款或一次实测上。

1. 在硬件描述语言中，"执行"的精确含义是什么？
   材料：调度语义里没有"执行语句"这回事，只有事件。定义在 1800 的 4.3：信号值的
   变化是更新事件（update event），进程因此要求值是求值事件（evaluation event）；
   事件与调度区的地图在 fundamentals/01 第 1 节。"执行一条赋值"落到机器上是"调度
   了一个更新事件"。检验：能说清 update event 与 evaluation event 各是什么
2. 是谁在执行 Verilog 的语句？
   材料：仿真器（把并发进程按时序调度）；综合器（把可综合子集映射成电路）读到
   的是同一份文本，做的是另一件事。Verilator 侧的执行者与顺序，fundamentals/03
   用调试轨迹逐区指认过。检验：能对着轨迹说出一次 eval 里各区先后的顺序与依据
3. if 的条件满足就不执行 else 后的语句，"不执行"是什么意思？
   材料：落到调度上是"else 分支的赋值事件不发生"；落到电路上是选择器在当前输入
   组合下选了另一路。第 3 节的锁存器正是"两条路都没说"的实测后果。检验：能用
   lat_bad 的例子解释"没说"如何变成"记住上次"
4. 并发执行、顺序执行、变量变化就执行、任何情况下都执行，分别怎么在电路里体现？
   材料：多个进程同拍都被调度是并发（标准 4.7 允许任意交织）；begin-end 内按
   源码顺序是顺序（标准 4.6）；@(*) 对输入持续敏感对应组合逻辑；assign 的持续
   有效对应连线（标准 4.9.1：连续赋值就是一个对右边敏感的进程）。检验：每问的
   答案能对上一条条款编号或一次实测

作答方式：书面写进你的学习记录，答案对错按上面的检验标准自查。

## 5 Chisel 的同一条纪律

讲义对 Chisel 持同一立场：when 和 switch 的语义与 Verilog 的行为建模相近，初学者
不用；选择器用 Mux1H 这类库函数。Chisel 生成 Verilog 后接入同一套 Verilator 与
NVBoard 流程。本项目的 Chisel 切换按计划在学完本章后进行，切换步骤见阶段 spec。

## 6 已知的坑

1. UNUSEDSIGNAL 的实测样本是未使用的端口（第 03 章 labs）；内部信号从不引用时报不
   报，本库没有实测记录，下"默认"结论之前先自己跑一遍
2. 多个模块塞一个文件会触发 DECLFILENAME（-Wall 下致命）：labs 的模板文件 tpl.v
   在构建时不加 -Wall 就能过，要严查时按模块分文件（第 01 章也踩过）
3. 行为版与模板版对照实验里，改任何一边的行为都要预判另一边跟不跟得上：labs 的
   三项改坏各自只错一处，靠的是独立计数（第 2 节的 mismatches）
