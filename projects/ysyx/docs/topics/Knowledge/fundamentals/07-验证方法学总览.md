## 1 验证方法学的层次（自下而上）

| 层 | 问题 | 手段 | 我们的对应 |
| --- | --- | --- | --- |
| 功能仿真 | 这个输入下行为对不对 | testbench + 自检（rand 驱动 + assert） | E4 批 1~3 在做 |
| 差分测试/协同仿真 | 全程每步行为与参考一致吗 | DUT vs REF 逐指令比对 | E4 批 8（DiffTest；REF=NEMU ISS） |
| 覆盖率 | 验证做完了吗（不是跑过，是覆盖过） | 代码覆盖（行/分支/翻转）+ 功能覆盖（覆盖点/仓） | UVM 线展开；Verilator 支持 5.02x 起部分功能覆盖（guide，版本敏感） |
| 断言 | 关键性质随时有人盯着吗 | SVA（SystemVerilog Assertions），时序性质声明式描述 | UVM 线展开；Verilator 5.x 支持部分 SVA（guide，版本敏感） |
| 形式验证 | 所有输入下性质成立吗 | model checking：把 RTL 当状态机穷举性质 | 后续阶段；开源可得 = SymbiYosys（Yosys 上层） |
| 方法学框架 | 上面这些怎么组织成可复用体系 | UVM（Universal Verification Methodology）：组件化 agent/sequence/ scoreboard | AMBA/UVM 线正课 |
| 抽象建模 | 比 RTL 更快的系统级仿真 | SystemC/TLM（事务级建模，CA/UNT/PVT 抽象级） | GPU 线 G 阶段相关，届时展开 |

## 2 参考模型生态（DiffTest 的 REF 谱系）

DiffTest 的 REF 本质是"同一 ISA 状态机的另一种实现"。谱系：

1. 自己写的 ISS（指令集模拟器）：E4 批 8 的 sEMU——最简形态，几条指令
2. NEMU：D 阶段的 REF（PA 主线产品，RV32IM，讲义官方配）
3. spike：RISC-V 官方 ISA 模拟器（riscv-isa-sim）——工业界做 golden model 的常用件
4. QEMU：全系统模拟器——工业界跑大程序/OS 级对照

共同点：都是"用程序状态机实现 ISA 状态机"（教程批 8 将展开）。工业界把这类 REF 叫 golden model；协同仿真（co-simulation）是 DiffTest 的正式学名。

## 4 本篇的用法约定

主线讲解遇到上表名词时：指到本篇对应小节讲清位置，不展开正课；正课在各自所属线（UVM 线/GPU 线/后续阶段）。本篇随各线推进保持地图更新，不做实验、不立判据。
