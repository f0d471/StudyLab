## 1 两种范式

### 1.1 事件驱动（event-driven）

代表：Icarus Verilog（iverilog，开源）；商业仿真器的交互与调试内核也含事件驱动成分。

机制（IEEE 1364-2005 第 11 章的事件调度模型）：仿真器维护一个事件队列。RTL 里的每个 always 块、assign、initial 是一个"进程"；某根信号变化即产生事件，事件入队，调度器取出事件、唤醒监听该信号的进程重新求值，可能产生新事件，直到当前时间片（含 delta cycle）没有事件为止，仿真时间才前进。一句话：**信号不变不算，变了才重算受影响的部分**。

优点：语义全。#延迟、四态 x/z、行为级描述、纯 testbench 语言特性都支持。缺点：逐事件解释执行，调度开销大，速度慢。

### 1.2 编译式（compiled / cycle-based）

代表：Verilator（开源）；商业仿真器的高性能模式（如 VCS 的 compiled mode）同属此思路。

机制：把 RTL 整体当作一门"前端语言"，走一遍编译器流程——解析成 AST、按实例化展开（elaborate）、静态优化，然后**生成 C++（或 SystemC）模型源码**，交给本地编译器（g++）编成机器码。跑仿真就是跑这个可执行文件，每个仿真周期是一次函数调用（eval），没有运行时调度。一句话：**把"仿真"提前编译成"程序"**。

优点：机器码速度，比事件驱动快一到两个数量级。代价：只支持可综合子集加部分仿真语句；#延迟这类不可综合描述没有意义（仿真时间由 testbench 的时钟驱动函数推进），四态压成两态。

### 1.3 范式对照表

| 维度 | 事件驱动 | 编译式（Verilator 一系） |
| --- | --- | --- |
| 执行方式 | 运行时调度进程，事件驱动 | RTL 预编译成机器码 |
| 仿真时间 | 事件队列推进，支持任意 #延迟 | testbench 代码显式推进（时钟函数） |
| 语义 | 全 IEEE 语义，四态 | 可综合子集为主，两态 |
| 速度 | 慢（数量级差） | 快 |
| 调试 | 交互强，随时改随时跑 | 改 RTL 要重新编译模型 |
| 典型用途 | 语义参考、行为级建模、小设计 | 大设计全量回归、性能仿真 |

## 2 两态与四态

四态：0、1、x（未知/未定）、z（高阻/没人驱动）。两态：只有 0、1。

- 四态的价值：建模"还没上电"和"总线悬空"。x 有传染性（0+x= x），能暴露"忘了复位"这类问题；代价是求值和传播要带状态集合运算，慢。
- Verilator 的选择：模型里全部压成两态。x 没了，"未初始化"由 `--x-initial` 决定初值策略（unique 尽量随机化以暴露未复位问题 / allN 全 0 等），"悬空/多驱动"在编译期由 lint 警告抓（UNDRIVEN/MULTIDRIVEN），运行期不再表达。
- 由此推论：**两态仿真器必须配 lint 纪律**——运行期不会出现的错误（x 传染）被压到了编译期和静态检查，开了 lint 才能兜住。这是 tutorials/E/04 3.3 节"建议总是开 lint"的机制级原因。

## 3 工具谱系

| 工具 | 所属 | 范式 | 状态 | 备注 |
| --- | --- | --- | --- | --- |
| VCS | Synopsys | 编译式为主，混合内核 | 商业闭源 | 业界主流；UVM/SVA/覆盖率全套集成 |
| Xcelium | Cadence | 混合（事件驱动+编译式并行） | 商业闭源 | 多核并行仿真见长 |
| Questa | Siemens EDA | 混合 | 商业闭源 | 与 ModelSim 同源，验证特性全 |
| Verilator | 开源（GitHub verilator/verilator） | 编译式 | 我们在用 | 快；两态；lint 顺手；本仓沙箱 5.052 |
| Icarus Verilog | 开源（steveicarus/iverilog） | 事件驱动 | 批 2 对照用 | 全语义、四态；小设计够用，慢 |
| GHDL | 开源 | 事件驱动 | 不用 | VHDL 的，提一句定位 |

商业工具没有许可证就摸不到，这不是损失：**范式理解和开源工具的手感是可迁移的**——VCS 的编译式内核、UVM/SVA/覆盖率这些"验证特征"是分层叠加的（学在 UVM 线），底层的"仿真"这一层，Verilator 和 iverilog 两只手已经把两种范式都练到了。讲义场景"老板说来试试 Verilator，写一份使用报告"：报告的骨架就是 tutorials/E/04 各章 + labs 实测——这套能力换个工具名照样成立。

## 4 什么时候用哪个（决策表）

| 你要干的事 | 用什么 |
| --- | --- |
| 可综合 RTL 的功能验证、全量回归、找性能 | Verilator |
| 验证一段含延迟/四态语义的行为模型或 testbench | iverilog |
| 需要交互式调试、单步、随时改 | iverilog（或商业工具，有许可证时） |
| 大 CPU + DiffTest 长跑 | Verilator（E5 起的主线，讲义同款选型） |
| 验证方法学（覆盖率/SVA/UVM） | 商业工具生态；开源对照见 07-验证方法学总览 |
