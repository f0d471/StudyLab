# 01 Verilator 的编译流水

    实验    npc 的 make sim（批 2 实做，对着产物逐阶段指认）
    依据    Verilator User Guide："Verilating"与"Simulating (Verilated-Model Runtime)"两章

这一篇讲 Verilator 作为编译器的内部流程和产出的模型长什么样。批 2 跑通 make sim 后对照产物读一遍；批 8 的 DiffTest 要访问模型内部寄存器，靠的就是本篇的"模型 API 面"一节。

## 你会在哪里撞见它

- tutorials/E/04 的 1.3 节："用 C 语言模拟"的精确含义在本篇展开
- 批 2 的 make sim：命令敲下去到可执行文件出现，中间每个阶段产物都能指认
- 批 8 的 DiffTest：`top->rootp->NPC__DOT__...` 访问 GPR——C++ 变量名怎么来的，本篇讲规则

## 这篇要回答的问题

1. 从 Verilog 文件到可执行文件，中间经过哪几个阶段，每阶段的产物是什么？
2. 生成的 C++ 模型对象长什么样：端口、内部信号、eval()、final() 分别是什么？
3. 和 gcc 的四步（预处理/编译/汇编/链接）怎么类比？

## 1 流水各阶段

| 阶段 | 干什么 | 产物 |
| --- | --- | --- |
| 1 读入与解析 | 词法/语法分析，认可综合子集 + 部分仿真语句 | 内部 AST（抽象语法树） |
| 2 展开（elaboration） | 参数化模块按每个实例化的参数生成具体电路；解出层次结构 | 展开后的 AST |
| 3 静态优化 | Verilator 的强项：常量折叠、信号合并、跨模块内联、死代码删除、寄存器分组 | 优化后的 AST（可用 --dump-tree 看） |
| 4 C++ 代码生成 | 按优化结果生成 C++ 模型类源码 | obj_dir/ 下 Vtop.h、Vtop.cpp 等 |
| 5 本地编译 | 生成 Makefile 并调用 g++，把模型 + 你的 --exe 文件编成可执行 | obj_dir/ 下可执行文件 |

与 gcc 四步的类比：gcc 的 cc1/as/collect2 对应这里阶段 1~3（前端）、阶段 4（"翻译成中间产物"，只是产物是 C++ 而不是汇编）、阶段 5（g++ 接管，真正编机器码）。Verilator 自己不产机器码，最后一步永远是本地编译器——这正是"编译式仿真器"名字的来源。

## 2 产物目录（obj_dir）

| 文件 | 内容 |
| --- | --- |
| Vtop.h | 模型类声明：端口成员、eval()/final() 原型 |
| Vtop.cpp、Vtop___024root*.cpp | 模型实现（eval 的函数体就是你电路的组合逻辑与时序逻辑的 C++ 翻译） |
| Vtop__Syms*.h/.cpp | 符号表：Verilog 信号名与 C++ 变量名的映射 |
| makefile、Vtop.mk | 阶段 5 的编译脚本 |
| <可执行文件> | 默认名 V+顶层模块名；--o 可改名 |

清单为典型形态；以批 2 实跑产物为准回填 labs/E/02（不同版本文件命名有差异，这正是"产物以实测为准"的原因）。

## 3 模型 API 面（testbench 视角）

模型类（如 Vtop）上你需要认识的接口：

1. **端口成员**：每个顶层端口对应一个 C++ 成员。1 位端口是 CData（uint8_t 别名），8 位是 CData，32 位是 SData/IData 按宽度定（头文件里看得见，批 2 实测确认）。赋值即驱动：`top->a = 1;`
2. **eval()**：让模型求值一次——组合逻辑传播到稳定；时序逻辑的时钟沿靠你改 clk 值再 eval 造出来（两次 eval 的原因见教程 3.2 节）
3. **final()**：仿真结束前的收尾（flush 波形缓冲等），循环外调一次
4. **内部信号访问**：`top->rootp-><层次名>` 可以伸进模型内部抓信号（如 GPR 数组）。C++ 名字由 Verilog 层次名变换而来：`.` 变 `__DOT__`，可读头文件或 __Syms 确认。规则随版本会变——讲义原话"可能会在修改 RTL 代码或更改 Verilator 版本时发生变化，需要手动同步修改"，批 8 用到时以当时实测为准
5. **波形挂钩**：编译期加 --trace-fst，运行期 Verilated::traceEverOn(true) + trace 对象（详见 05-波形格式与GTKWave）

## 4 两个易混点

1. eval() 不是"执行一条语句"，而是"求值到稳定"。组合电路一次收敛；时序逻辑在 clk 沿的 eval 里采样更新。
2. 生成的 C++ 不是"翻译你的代码逐句执行"，而是整块电路的数学等价物（直接是位运算和分支）。这也是两态语义的来源之一：x 的语义运算在静态优化阶段被消掉了。
