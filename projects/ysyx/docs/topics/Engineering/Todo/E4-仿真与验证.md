## 一、定位

- E4《处理器的仿真和验证》是 2607 版阶段制讲义的第一个动手阶段。官方标 5 课时（对熟练者），我们按九批走，预估 15~25 个学习单元。
- E4 一次立起整条工具链：Verilator 仿真 → 波形 → NVBoard 虚拟板卡 → lint → RTL 实现 sCPU → sEMU 指令级模拟器 → DiffTest 差分测试。这条链是 E5（minirv）→ D8（RV32E NPC）→ C4（AXI4 SoC）一路放大的模板：E4 把流程跑通，后面全是同流程、更大规模。
- 讲义的两个训练重心与本仓既有规矩同频：①项目所有细节自己搭，不从等框架开始（对应"提交即更新文档"）；②DiffTest 之前先让测试能报错（讲义要求注入错误观察报错；与 [Bugs/README](../Bugs/README.md) 的"先证明你的测试能报错"铁律一字不差，现场互证）。
- E4 是重点精读章节：仿真验证直接服务 GPU 自研线（G1 命令环、DMA、SoC 集成都踩在这上面），不快走。

### 学好的三层标准（2026-11-13 用户定调，适用于全部学习线）

1. 完成当下任务（讲义/项目判据）——只是底线
2. 看懂学术界的知识——原理与标准，不是只会用工具
3. 经得起公司的考验——理解工业界真实工具谱系与分工，拿不到的商业工具要有开源对照学习

依据此标准，E4 的 tutorials/fundamentals 不只覆盖讲义操作，还覆盖"仿真和验证"作为一门学科的知识地图（下表；批 1 起按需开篇，阶段外的只登记不展开）：

## 二、依赖与递进链

讲义给 NPC 垫的四级台阶：

| 台阶 | 阶段 | 讲义事实 |
| --- | --- | --- |
| sCPU | F5 Logisim → E4 RTL | sISA：8 位 PC、4 个 8 位 GPR（R[0..3]）、256B 内存、4 条指令 add/li/io/bner0；F5 路径=先做只有 li 的 CPU 再逐条加 |
| minirv NPC | E5 | E5 开头：sCPU"由于各种限制，无法运行更复杂的程序"；从 RV32I 挑 8 条指令替代全部 42 条功能，GPR 数量对齐 RV32E；模块化划分 IFU/IDU/EXU/LSU/WBU |
| RV32E NPC | D8 | D8 开头：将 NPC 的 ISA 从 minirv"升级"为 RV32E（约 40 条指令） |
| RV32IMAC + 流水线 | A / B4 | D8 明说 A 阶段再升级 RV32IMAC |

- sCPU 不是新讲义新加：2407 旧版阶段制讲义就有 F5；一周目走旧 PA 路线，没有这个台阶。
- DiffTest 的 REF 全程是 NEMU（RV32IM；RV32E 程序可直接跑在 RV32IM 上，无缝）。
- 硬依赖：E4 中段"用 RTL 实现 sCPU"要求先有 F5 在 Logisim 里搭的 sCPU 电路图。一周目未做过 Logisim sCPU，第 6 批补课。
- 语言底子：Verilog 和 C 有 gfx2d 实战底子，不需补课。

## 四、语言决策：NPC 用 Chisel（已定）

- 官方一等公民：讲义明说"一生一芯并不限制你使用何种语言来设计处理器"；官方模板 `OSPU/chisel-playground`，`./init.sh npc-chisel` 一键切换。讲义自己的建议："先按讲义内容搭建好 Verilog 的工作流程，完后再切换"。
- 模板实测：mill 1.1.0 构建（非 sbt）+ Scala 2.13.18 + **Chisel 7.16.0** + scalatest；`make verilog` 出 Verilog 到 `build/`；模板 Makefile 同样保留 `git_commit` 追踪命令；自带 GCD 示例。沙箱有 OpenJDK 17，无 mill/sbt（mill 单二进制装一次）。
- **切换时机按方案 A**：第 0~4 批用 Verilog（练的是仿真框架和接口，语言无关），第 4 批末切 Chisel，第 5 批起全用 Chisel。理由：数电五连是 Chisel 练手的完美场地（小、判据落在 NVBoard 可视行为、风险低），E5 真处理器不该同时背新语言和新架构。方案 B（E5 初切）仍可改，改动只影响第 4 批末的动作。
- 切换前必须先 commit 备份 npc（红线 §六 第 2 条）：`init.sh npc-chisel` 会 `rm -rf npc` 整体替换。
- 模板不带 NVBoard/Verilator 集成，生成的 Verilog 接回 npc.mk 仿真框架是自己的工程活（约半天量级，前期研究课题 R-03）。E5 与 C++ 存储器交互走 BlackBox + DPI-C（讲义明示）。
- 讲义对 Chisel 的规范立场：初学者不用 `when`/`switch`（语义近似行为建模），用 `Mux1H` 等库函数；firtool 生成 Verilog 的 lint 警告在确认不影响逻辑后可忽略，但 lint 始终开着；生成代码信号名与 Chisel 源有映射成本（E4 模块小可控；D8 起 itrace/difftest 基础设施好了，对波形依赖下降）。ysyxSoC 外设全是 Verilog，读 Verilog 的能力在 Chisel 路线同样必需。
