# 通用学习平台

StudyLab 是课程与研究实验的共同载体。这里维护可运行的项目、必要资料、实验记录和环境；每个项目说明自己研究什么、用什么判据检查、还有哪些未完成。

本文是平台唯一说明文档，2026-10-19 起由原「通用学习平台」「开发环境」「环境改造记录」三份合并而成，三节分别回答：平台怎么用、环境现状是什么、环境是怎么改造成现在这样的。

### 日常使用

在 Workspace 根目录执行：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Doctor -Project ysyx
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Shell -Project ysyx
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Shell -Project cs61b
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Run -Project cs61b -Command @('python3','-B','tools/smoke.py')
```

在 WSL 终端执行同一入口：

```bash
bash /mnt/e/Workspace/Tools/wsl-sandbox/run.sh --project ysyx shell
bash /mnt/e/Workspace/Tools/wsl-sandbox/run.sh --project cs61b run python3 -B tools/smoke.py
```

进入后项目映射到 /workspace，YSYX 默认位于 /workspace/ysyx-workbench。普通课程不会继承 NEMU_HOME 等变量。exit 结束会话；Ctrl+C 中止前台任务。会话含等待输入在内最多 30 分钟。

GUI、联网和 GPU 都需要项目描述声明，再用 -Gui、-Network、-Gpu 显式开启。cs336 的 GPU 查询只验证设备通路，完整训练需要另外安装并验证依赖。详细限制见[开发环境](#开发环境)。

### 接入新项目

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Add -Project xv6 -Kind course
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Shell -Project xv6
```

Add 只创建项目目录、project.json、学习约定占位并登记，不下载源码或安装依赖。已有非空目录需要显式 -Existing；不覆盖已有描述文件。不再学习时先保存成果与引用，再从注册表移除；清理代码与数据是单独操作。

在项目 README 填写问题、前置条件、来源版本、首轮范围、完成判据和未完成项。按课程自身结构组织源码，必要时增加 notes/、tools/、results/；虚拟环境、大数据、模型、波形和构建产物忽略。共享代码或输入通过 project.json 的 sharedInputs 声明，只读映射到 /inputs/<名称>。

### 实验与证据

课程单元以解释、题目和实验为完成依据；研究记录包括问题、假设、基线、变量、命令、原始数据和限制。功能正确与性能收益分别验证。失败与否定结论有保留价值，不能因为没有改进就删除。

运行记录在 logs/<项目 ID>/，包含项目、argv、代码版本、dirty 状态、资源池、能力开关与退出码。交互只保存会话元数据，普通终端输入输出不自动录制。YSYX 迁移前的证据保留在其项目 logs/，通过[环境改造记录](#环境改造记录)查旧路径。

平台共享资源与工具版本，各项目独立 HOME 和依赖。各项目按实际需要登记资料来源、版本和用途，材料与说明保持明确归属。

## 开发环境

更新：2026-10-17。StudyLab 使用原 12 GiB 固定 NTFS VHDX，Windows 入口为 E:\Workspace\StudyLab，WSL 管理挂载为 /mnt/wsl-sandbox/studylab。底层 ysyx.vhdx、卷 GUID 与 token 保留，显示名称与项目 ID 已分离。

### 入口与配置

通用工具在 Workspace/Tools/wsl-sandbox；profiles/studylab.json 管理卷和共享资源，profiles/ysyx.json 是兼容重定向。platform/projects.json 登记项目目录，各项目 project.json 管理 cwd、环境、能力、时限与只读共享输入。

Windows PowerShell 5.1 与 PowerShell 7 均支持：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action List
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Doctor -Project cs61b
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Shell -Project ysyx -Gui
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Run -Project cs336 -Gpu -Command @('/usr/lib/wsl/lib/nvidia-smi')
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Stop -Project cs61b
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Stop -All
```

默认项目为 ysyx。WSL 使用 bash /mnt/e/Workspace/Tools/wsl-sandbox/run.sh --project <ID> shell，或 run 后跟 argv。参数通过数组和 Base64 JSON 传输，systemd-run 关闭环境展开，空格、引号、中文与字面美元符号保持原样。

### 共享限制与文件视图

| 对象 | 范围 |
| --- | --- |
| 内存 | 全平台累计 3 GiB，2.5 GiB 开始回收，零 swap |
| CPU | 全平台累计 200% CPU 时间，约相当于 2 核 |
| 进程与线程 | 全平台累计 256 |
| 会话 | 每次最多 30 分钟，含等待输入；项目只能设更短时限 |
| 临时盘 | 每次 256 MiB tmpfs，同时计入内存 |
| 普通文件 | 单文件最多 2 GiB；core dump 关闭 |
| 持久数据 | 整卷 12 GiB；少于 256 MiB 拒绝启动任务，安装前另估峰值 |

各项目子 slice 共用 studylab.slice 的上限，Stop -Project 不停止其他项目。平台只给当前项目 /workspace、独立 /home/sandbox 与 /cache 写权限；系统目录、共享工具和声明的 /inputs 为只读。宿主 HOME、其他项目与 Windows 互操作不开放。网络、GUI、GPU 都需在描述中声明，再显式启用。

YSYX 的 cache 保留在其项目内部，兼容原工具的相对布局；其他项目缓存默认在平台 cache/<ID>。Verilator 5.052 保留原安装目录，在 /toolchains/verilator-5052 只读共享。其他项目使用时在自己的环境设置 VERILATOR_ROOT=/toolchains/verilator-5052/share/verilator，并将相应 bin 加入 PATH；不复制工具。

### NTFS 与依赖

当前新挂载使用 metadata、case=off，不修改 Windows ACL。case=dir 曾使新目录的大小写标记操作被 NTFS 权限拒绝；改用 case=off 后目录创建和编译运行通过。此设置意味着本挂载按不区分大小写语义工作；需要仅大小写不同文件并存的项目须另行选择合适文件系统或配置，不能静默覆盖。依据见 [微软大小写说明](https://learn.microsoft.com/en-us/windows/wsl/case-sensitivity)。

WSL 系统包共享，项目自己的 Python venv、Java 缓存和锁文件分开；源码在 Windows 编辑，Linux 可执行位与符号链接保留。现有基础工具来自已记录的 WSL 安装；本轮未安装整套新课程依赖。

GPU 通过显式 -Gpu 开放 /dev/dxg 与只读 WSL 驱动库。设备查询已识别 RTX 4060 Laptop；CPU cgroup 不限制 GPU 显存。CUDA 工具链、PyTorch、训练、多卡与大模型未在本轮验证，cs336 尚未安装课程作业。GUI 共享显示服务，不作为恶意代码的完整安全边界。

### 挂载与恢复

WSL 挂载由配置生成的 systemd mount unit 随 local-fs.target 恢复，前提是 Windows 已连接 VHDX；Setup 和 Mount 不再向 fstab 写卷条目。Windows 自动连接由 StudyLab-AttachVolume 计划任务提供。使用通用工具安装、查看或关闭：

```powershell
& .\Tools\wsl-sandbox\startup.ps1 -Action Install
& .\Tools\wsl-sandbox\startup.ps1 -Action Status
& .\Tools\wsl-sandbox\startup.ps1 -Action Remove
```

任务由 SYSTEM 在开机 15 秒后连接原 VHDX，安装账户登录时再补试；失败后每分钟重试，最多三次，电池供电时也允许运行。安装和关闭任务按需要使用正常管理员入口，自动执行时不弹确认窗口。任务保存固定代码与卷身份，修改模板或卷路径后需重新 Install。Remove 不断开现用卷；任务不会启动用户 WSL，Ubuntu 启动后沿用现有挂载单元。

未安装任务或自动连接失败时，StudyLab 挂载点虽然可能保留卷 GUID，目录仍不可访问。在 Workspace 根目录手动恢复：

```powershell
& .\Tools\wsl-sandbox\sandbox.ps1 -Action Mount
```

Mount 同时检查卷 GUID 与实际卷信息是否可读，必要时经正常管理员入口 Attach 原 VHDX，再恢复 WSL 挂载并运行 Doctor。仅保留挂载点不视为已连接。缺卷、错误身份或限额不符时拒绝运行，不退回普通目录。2026-10-17 的故障与恢复范围见[重启后挂载恢复](#重启后挂载恢复2026-10-17)。

原卷状态仍在 Tools/wsl-sandbox/state/ysyx.json，与卷内 .wsl-sandbox-volume.json 保持一致。重装与备份应覆盖平台仓、各项目仓、未提交材料、原始证据、HOME 与卷外 profile/state；只备份 ysyx-workbench 无法恢复整个平台。迁移原状态与恢复映射见[环境改造记录](#环境改造记录)。

### 重启后挂载恢复（2026-10-17）

Windows 最近启动时间为 2026-10-17 07:07:06；排查时原 ysyx.vhdx 存在，但 Get-DiskImage 的 Attached 为 false。StudyLab 重解析点仍指向已登记卷 GUID，卷未出现在在线卷列表，目录无法打开。

原 Windows 入口只调用 GetVolumeNameForVolumeMountPoint，残留的挂载点仍能返回预期 GUID，导致 Mount 跳过 Attach，随后读取卷内标记时报路径不存在。现增加 GetVolumeInformation 检查实际可访问状态，并在 Attach 后复查；错误卷身份直接拒绝。

本轮未主动重启 Windows，也未断开已恢复的原卷进行回归；自动审批因活动卷中断或数据损伤风险拒绝后者。模拟分支检查不能替代真实断开或冷启动端到端验证。故障诊断、检查结果、源码身份登记与原始日志位置集中在[恢复记录](../../Tools/wsl-sandbox/state/windows-recovery-20261017.json)。Windows 重启后的日常恢复命令见[挂载与恢复](#挂载与恢复)。

### 开机自动挂载（2026-10-17）

已安装 StudyLab-AttachVolume 计划任务，由 SYSTEM 执行。开机延迟 15 秒触发，安装账户登录时补试；失败后每分钟重试，最多三次，电池供电时也允许执行。任务最多运行两分钟，重复触发不并发启动。

启动动作保存固定的 PowerShell 代码和原卷身份，不从可写工作区执行脚本或读取配置；模板和安装入口分别为 Tools/wsl-sandbox/startup-mount.ps1、startup.ps1。任务所有者为 Administrators，仅 SYSTEM 和 Administrators 可修改，普通用户可读。运行时只对已登记的原 VHDX 执行 Attach 与挂载点恢复，并核对磁盘 ID、容量、卷 GUID 和卷内标记。

安装后实际启动 SYSTEM 任务，返回码为 0，原卷保持可读；触发器、电池条件和重试设置均已回读核对。本次验证在原卷已连接时执行，未重启 Windows，也未断开原卷验证 Attach 分支。安装结果、测试范围与源码及任务内容身份登记集中在[自动挂载记录](../../Tools/wsl-sandbox/state/windows-startup-mount.json)。状态与关闭命令见[挂载与恢复](#挂载与恢复)。
